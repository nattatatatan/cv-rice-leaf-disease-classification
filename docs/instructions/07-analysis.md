# 07 - Analysis: tables, figures, failure cases, Grad-CAM

Goal: turn run folders into every number, table and figure the report needs. All of it is generated by `python <group_name>.py summarize` (plus `gradcam`), so the results are reproducible. Nothing is computed by hand in a spreadsheet.

Prerequisites: runs exist (this phase grows incrementally; build `summarize` right after the first E0 batch). Notebook: `notebooks/50_analysis.ipynb`.

## Conventions
- Numbers: `mean +- std` over 5 splits, 3 decimals for F1 (0.912 +- 0.014), 1 decimal for accuracy in % (91.2 +- 1.4).
- Every table is written as both `.csv` (for Word) and `.md` (for review in the repo).
- Figures: PNG, 300 dpi, readable at half A4 width, colour-blind-safe palette, same class order and colours in every figure, white/field shown with consistent markers.

- [x] All eight tables are written by `summarize`. `table_required` marks the recommended row; `table_per_class` is the recommended method per class and domain (mean +- std over the 5 test splits, support summed); `table_hparams` reads every value from `config.json` (a value that differs between splits reads `varies:` and is named in the caption); `table_runtime` reads `metrics.json` and `env.json`.
- [x] Inference ms/image is not measured by `summarize` (that would make results non-reproducible). `benchmark [--device D]` times the forward pass of the three backbones (untrained weights, batch 1, 10 warm-up passes, median of 50) and merges the record into `_work/results/inference_benchmark.json`, one entry per device; `summarize` reads it into `table_runtime`, else the column reads `not measured (run benchmark)`. The committed file holds the Mac CPU and MPS measurements.

### T7.5 Grad-CAM (Tier 4)
- **Grad-CAM** colours the image regions that most increased the predicted class's score, computed from the gradients at the last convolutional (or Swin) stage. We use it to check whether the model looks at the leaf or at the background (a shortcut).
- Checkpoints: the reported runs did not keep `best.pt`, so Kaggle batch `batch5-checkpoints` retrained E2-swin-U (plain) and E3-A (Method A) into `runs/retrain/<ID>/split_k/` with `best.pt` kept (`.pt` is gitignored; the other run files are committed). The retrain is deterministic: `predictions_test.csv` and `predictions_val.csv` are byte-identical to the reported runs on all 10 splits (only timings differ), so Grad-CAM explains exactly the reported models. `runs/retrain/` is in `IGNORED_RUN_FOLDERS`, never a result. Method B was cut at G2, so the comparison is plain vs A.
- [x] Implement with forward/backward hooks on `gradcam_target_layer` (T3.3); no extra packages. `grad_cam` (a forward hook keeps the layer output, `torch.autograd.grad` gives the class-score gradient, hook removed in a `finally`), `cam_on_image` maps the map back onto the original photo (undoes the `pad` letterbox; tested with a synthetic brightness network under squash, pad and rect), `explain_images` runs the exact evaluation pipeline of the checkpoint. Predicted class explained by default.
- [x] `gradcam [--exp ID] [--compare ID] [--split k] [--runs-dir DIR]` writes `gradcam_success.png` and `gradcam_failure.png` (the images of the T7.4 contact sheets, same selection; photo | plain `E2-swin-U` | Method A `E3-A`, each labelled `true -> pred (p)` on one test split) and `gradcam_annotated.png` (8 annotated images with the polygon outline). Checkpoints default to `runs/retrain/`; without `--split` the command also writes `findings.md` section `auto:gradcam`, which `summarize` leaves alone. Run on the Mac with MPS (about 25 s).
- [x] **Quantitative shortcut check** (sample chosen by Nattan, deviating from the 20 eval images of the plan): all 30 annotated field images (dev and eval; dev only tuned the segmenter), each counted in every split where it was a test or validation image, never a training image: 43 (image, split) pairs from 24 images. Share of the Grad-CAM energy (predicted class) inside the annotated leaf polygon, against the polygon's area share (chance), written to `gradcam_energy.csv` and `table_gradcam.{csv,md}`. Headline: leaf area share 0.072; plain 0.244 +- 0.192, Method A 0.240 +- 0.209 (both about 3.4x chance); paired A - plain -0.004 +- 0.136, A ahead in 17 of 43 pairs; per image (24) +0.011 +- 0.138. Both models put far more of their map on the leaf than chance, and Method A does not move it: an honest negative finding for the "composites teach the model to ignore the background" motivation. Method B was cut, so the comparison is plain vs A.
